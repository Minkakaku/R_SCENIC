# 项目分层

实际项目统一位于 `/workspace/projects/<项目名>/`，同一项目只建一次，R/Python 共用 `config/`、`workflow/`、`data/`、`results/` 和 `logs/`。公共方法保留在对应代码仓库的 `src/R/` 或 `src/python/`，公共默认与环境定义保留在代码仓库 `config/`、`envs/`。

每个实际项目仅在本地拥有独立 Git 仓库，用于本地版本记录；只有公共代码库放在 GitHub，项目代码、配置和数据保留在本地。初始化时按需从 GitHub 以子模块检出公共库到项目 `deps/`，通过 `.gitmodules` 记录来源、子模块指针固定提交。从本地项目或备份恢复时获取已记录的依赖版本，分析启动不自动拉取最新版；升级依赖须单独验证和记录。

项目共用样本表、分组、人工注释和配色；方法参数可放 `config/methods/` 并由项目 `config/config.yaml` 引用。项目共用配置覆盖公共默认，方法参数可继续覆盖本方法默认值，不另行定义共用元数据。项目相对路径以项目目录为基准，代码仓库根目录显式指定。

编号步骤按分析顺序混合使用 R/Python，仅加载配置、调用公共方法和写日志。中间对象与显式转换产物放项目 `data/processed/`，正式图表放项目 `results/编号_分析点/`。保留已运行步骤；重跑可复用原步骤，确需修改已运行脚本时新增步骤并记录来源。`results/` 的编号固定对应分析点，由项目配置维护；同一分析点重跑、调整参数或补图仍使用原目录并更新对应产物，不按运行次数新增结果目录。仅新增分析点时分配新的结果编号。运行批次、参数与代码版本追加到 `logs/README.md`，原始运行日志另存 `logs/`。

仓库内 `projects/project1/` 仅为未运行的兼容示例，当前加载器仍依赖旧布局。集中项目接入前先适配显式代码仓库路径和共用配置，再建立统一模板、验证路径与跨语言交接，最后迁移实际项目；不能直接复制旧模板到集中目录运行。完整规则见 `/workspace/AGENTS.md`。

每个项目在 `logs/README.md` 维护唯一的项目总记录，汇总项目概况并按时间追加所有操作，包括检查、依赖与代码变更、参数调整、人工决策、运行、失败、重跑和结果核对；每条注明时间与时区、目的、脚本或命令、输入与参数、代码和环境版本、状态、日志及固定结果路径。根目录 README 作为入口和运行索引，链接到总记录。总记录纳入项目本地 Git，原始运行日志忽略；项目内容不上传 GitHub。
